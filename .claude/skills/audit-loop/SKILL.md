# Audit Loop («гол луп»)

Юсуф (владелец, не разработчик) хочет, чтобы система улучшалась циклами:
каждые ~5 часов проект осматривается ЗАНОВО, как будто это делает посторонний
придирчивый человек, не знакомый с кодовой базой и не привязанный к прошлым
решениям. Цель каждого круга — «ни одного изъяна»: удобно, красиво, быстро,
надёжно.

## Режим общения

Юсуф пишет голосом, поток мыслей, на русском. Отвечай по-русски, без
жаргона, объясняй «на пальцах». Не задавай подтверждающих вопросов — он
явно разрешил всё делать самостоятельно (включая merge). Смысл просьб
важнее буквы: «сделай чётенько» = цельно, надёжно, приятно пользоваться
каждый день (см. скилл creator-vibe, если установлен).

## Круг аудита — обязательные шаги по порядку

1. **Свежий взгляд.** Прочти docs/audit/ (прошлые круги — их находки НЕ
   повторяй) и верхние записи docs/PROGRESS.md. Затем осмотри систему как
   посторонний: пройди глазами каждый экран Mini App (webapp/src/components),
   каждый ответ бота (courier_templates, тексты хендлеров), каждый пустой/
   ошибочный стейт. Ищи то, что смутит ОБЫЧНОГО пользователя: непонятные
   тексты, мёртвые кнопки, неочевидные флоу, некрасивые стыки, медленные места.
2. **Многоагентный поиск багов.** Ultracode включён — используй Workflow:
   агенты-аудиторы по областям (бот, AI-пайплайн, API, БД/фон, фронт-данные,
   фронт-UI, перф) + адверсариальные верификаторы на каждую находку
   (задача верификатора — ОПРОВЕРГНУТЬ). Правило «сомневаешься — не включай».
3. **Сверка с интернетом.** Проверь актуальность моделей Groq
   (deprecations!) и ключевых практик — веб-поиском, не по памяти.
4. **Фиксы.** Исправь подтверждённое: критичное — обязательно, важное — по
   максимуму, минорное — если дёшево. Root-cause, минимальный дифф
   (скилл ponytail). На каждый бэкенд-фикс — регрессионный тест.
   **Железное правило (урок круга 2):** фикс без теста, который падает БЕЗ
   него, считается несделанным. В круге 1 хелпер перестройки списка `/today`
   был написан, но не подключён ни к одному обработчику — тесты этого не
   заметили, а PROGRESS и аудит-файл уже отрапортовали «исправлено». Перед
   тем как писать «сделано», грепни, что новый код действительно вызывается.
5. **Аудит-файл.** Новый docs/audit/<дата>-audit-round<N>.md: методика,
   все находки с вердиктами, что исправлено, что отложено и почему.
6. **Документы.** Обнови docs/PROGRESS.md (новая секция сверху: Контекст /
   Сделано / Верификация / Не сделано), шапку docs/HANDOFF.md, статус в
   docs/ROADMAP.md.
7. **Гейты.** /gates: uv run ruff format --check . && ruff check . && mypy app
   && pytest -q; в webapp/: npx tsc --noEmit && npm run build. Всё зелёное —
   иначе чини, не пуши красное.
8. **Пуш → PR → мердж.** Ветка claude/... (если прошлая смержена — новая от
   свежего main). PR с описанием по .agents/skills/writing-prs/SKILL.md.
   Дождись зелёного CI (poll), смержь squash сам. НЕ жди одобрения.
9. **Деплой-чек.** После мержа — скилл deploy-check (Render, модели, healthz).
10. **Таймер следующего круга — ТОЛЬКО по явной просьбе.** Автоматически
    send_later НЕ ставим: 2026-07-26 Юсуф сказал «триггер удали, теперь он
    не нужен» и таймеры сессии удалены. Круг запускается его сообщением
    («сделай ещё круг», «проверь свежим взглядом»). Если он снова попросит
    автоматический цикл — тогда send_later на ~5 часов с промптом
    [GOAL-LOOP, круг N+1].

## Чего НЕ делать

- Не повторять находки прошлых кругов ради объёма — только новое.
- Не рефакторить ради рефакторинга: каждый дифф отвечает на конкретную
  находку.
- Не менять продуктовые решения (дизайн-язык webapp/DESIGN.md, выбор
  моделей, структуру фаз) без явной просьбы — фиксируй сомнение в
  аудит-файле как «вопрос Юсуфу».
- Не коммитить секреты; parse_mode на пользовательских строках запрещён;
  naive-UTC дисциплина (docs/HANDOFF.md «Грабли»).
