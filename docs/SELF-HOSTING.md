# Запуск на своём сервере (вариант Б)

Один контейнер, никаких внешних сервисов: ни Render, ни Supabase, ни
Neon. Скопировал файлы, вписал два ключа, запустил — работает.

## Что нужно от сервера

- Docker с плагином Compose (`docker compose version` отвечает).
- Свободный диск: образ качается ~80 МБ, на диске занимает ~250 МБ.
  База растёт медленно — тысяча задач это единицы мегабайт. С запасом
  под обновления образа хватает **500 МБ**.
- Исходящий интернет. **Входящие соединения, домен, сертификат и
  открытые порты НЕ нужны** — бот работает в режиме polling, то есть
  сам ходит в Telegram.

## Установка

```bash
# 1. Забрать репозиторий
git clone https://github.com/Itosyro/plan-app.git
cd plan-app

# 2. Заполнить два ключа
cp .env.server.example .env
nano .env      # TELEGRAM_BOT_TOKEN и GROQ_API_KEYS

# 3. Запустить
docker compose up -d
```

Всё. Образ скачается готовым (собран в GitHub Actions), база создастся
сама в `./data/plan.db`, схема поднимется на старте.

Проверить, что живо:

```bash
docker compose ps                         # состояние healthy
curl -s localhost:8000/healthz            # {"status":"ok",...}
docker compose logs -f app                # живой лог
```

Дальше — просто напиши боту в Telegram.

## Обновление

```bash
cd plan-app
git pull
docker compose pull && docker compose up -d
```

Миграции применятся сами. База в `./data` переживает обновление —
контейнер пересоздаётся, файл остаётся.

## Если образ не скачивается (приватный репозиторий)

GitHub Packages требует логина для приватных репозиториев. Нужен
[токен](https://github.com/settings/tokens) с правом `read:packages`:

```bash
echo ВАШ_ТОКЕН | docker login ghcr.io -u Itosyro --password-stdin
docker compose pull
```

Либо собрать образ прямо на сервере — но для этого нужно **≥4 ГБ**
свободного диска (сборка тянет `node_modules` и компиляторы):

```bash
docker compose build && docker compose up -d
```

## Мини-приложение (необязательно)

Бот в переписке работает сразу. Мини-апп (доски, канбан, календарь) —
это веб-страница, а Telegram открывает такие страницы **только по
HTTPS**. Нужен публичный адрес — вариантов три.

### Вариант 1: прокси провайдера (проще всего)

Многие хостинги (exe.dev, Fly, Railway, Render) сами дают HTTPS-адрес и
сертификат: в панели указывается, какой порт машины публиковать. Тогда
ни Caddy, ни Let's Encrypt не нужны.

1. В панели укажи порт **8000**.
2. В `.env` добавь `APP_BIND=0.0.0.0` — иначе контейнер слушает только
   localhost, а прокси приходит по сетевому интерфейсу и упирается в
   закрытую дверь.
3. Туда же `MINIAPP_URL_OVERRIDE=https://твой-адрес/app/`.
4. `docker compose up -d`.

Если провайдер публикует **только один порт**, а он уже занят другим
твоим сервисом — смотри вариант 3.

### Вариант 2: свой домен

Направь домен на сервер, поставь Caddy (сам получает и продлевает
сертификат) и проксируй на `127.0.0.1:8000`. `APP_BIND` менять не надо.

### Вариант 3: делим один порт между проектами

Ситуация: провайдер публикует ровно один порт, а он уже занят другим
твоим проектом. Отбирать порт нельзя — сосед может ходить через вебхук
и молча перестанет работать. Ставим маршрутизатор: он занимает
публичный порт и делит трафик по путям. Сосед продолжает отвечать на
своём прежнем адресе и подмены не замечает.

Конфиг (`Caddyfile`) и сервис `router` уже лежат в репозитории.

**1. Убедись, что пути свободны.** Мини-апп забирает `/app` и `/api` —
если сосед сам их использует, будет конфликт:

```bash
curl -s -o /dev/null -w "/     → %{http_code}\n" localhost:3002/
curl -s -o /dev/null -w "/api  → %{http_code}\n" localhost:3002/api/
curl -s -o /dev/null -w "/app  → %{http_code}\n" localhost:3002/app/
```

`404` на `/api` и `/app` — путь свободен, продолжай. Если сосед на них
отвечает осмысленно — напиши, поменяем префиксы.

**2. Пропиши порты в `.env`** (значения по умолчанию — в скобках):

```
ROUTER_PORT=3003
NEIGHBOUR_UPSTREAM=127.0.0.1:3002
MINIAPP_URL_OVERRIDE=https://твой-адрес/app/
```

**3. Подними маршрутизатор** (`--profile router` — иначе он не стартует):

```bash
docker compose --profile router up -d
```

**4. Проверь ДО переключения** — сосед и мини-апп должны отвечать через
новый порт:

```bash
curl -s -o /dev/null -w "сосед    → %{http_code}\n" localhost:3003/
curl -s -o /dev/null -w "мини-апп → %{http_code}\n" localhost:3003/app/
```

Ожидаем: сосед — как и раньше на 3002, мини-апп — `200`.

**5. Только теперь** переключи в панели провайдера публикуемый порт с
`3002` на `3003`. Если что-то пойдёт не так — вернуть прежнее значение
это одно движение, сосед даже не перезапускался.

TLS настраивать не нужно: сертификатом занимается прокси провайдера,
внутрь приходит обычный HTTP.

### После настройки

Пропиши адрес в `.env` и перезапусти — бот сам поставит кнопку
«Открыть план» рядом с полем ввода:

```
MINIAPP_URL_OVERRIDE=https://твой-адрес/app/
```

## Бэкап

Вся база — один файл. Копировать можно на живом контейнере:

```bash
docker compose exec app sqlite3 /app/data/plan.db ".backup '/app/data/backup.db'"
cp data/backup.db ~/plan-backup-$(date +%F).db
```

## Если мало места

```bash
docker system df                  # что сколько занимает
docker system prune -af           # снести неиспользуемые образы и кэш
```

Логи ограничены (3 файла × 10 МБ) — бесконтрольно расти не будут.

## Чем отличается от управляемого деплоя

| | Свой сервер | Render |
|---|---|---|
| Получение сообщений | polling (исходящие) | webhook (входящие) |
| База | файл SQLite | Postgres (Supabase) |
| Домен и TLS | не нужны | нужны, даёт платформа |
| Миграции | сами на старте | отдельной командой |
| Засыпание | нет | free-tier засыпает |

Переключение — одна переменная `BOT_MODE`. Код общий, ветвление
только в момент старта (`app/main.py`).

**Важно:** одновременно два экземпляра (Render и свой сервер) с одним
токеном запускать нельзя — Telegram отдаёт сообщение кому-то одному, и
поведение станет случайным. Перед переездом останови старый.
