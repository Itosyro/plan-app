## 7 · Известные мелочи / debt

- `PENDING_CLARIFICATIONS` in-memory: нормально для текущего single-process Render, но при нескольких workers будет теряться между процессами. Если масштабируемся — перенести в Postgres table или Redis-like store.
- `cancel_reminder` отменяет pending reminders, но не пишет `TaskEvent`. Это осознанно маленький PR-J slice; если нужна audit history reminder changes — добавить отдельным PR.
- `/reminders` показывает только upcoming pending. Overdue pending строки обрабатывает scheduler; если scheduler лежал долго, пользователь их не увидит в “upcoming”, что теперь соответствует названию команды.
- Handoff v19 всё ещё содержит старые указания про ручной REST/curl merge от Devin. В Capy-среде использовать встроенные `create_pr`/`git_push`, а merge — только при явном запросе пользователя.
