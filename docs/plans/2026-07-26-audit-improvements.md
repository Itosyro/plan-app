## Будущее: мобильное приложение (ответ на вопрос Юсуфа)

Сейчас продукт живёт в Telegram (бот + Mini App). Mini App — это уже
веб-приложение, оно УЖЕ работает на телефоне внутри Telegram. Путь к
«отдельному приложению на iPhone/Android» поэтапный, без переписывания:

1. **PWA (первый шаг, дёшево).** Тот же webapp/ раздаётся по /app.
   Добавляем manifest.json + service worker — приложение можно «Установить
   на экран Домой» из Safari/Chrome, оно открывается без Telegram.
   Понадобится вход без Telegram initData (одноразовый код от бота или
   магическая ссылка). Это же даёт первый offline-слой: service worker
   кэширует оболочку, данные — из существующего кэша.
2. **Capacitor-обёртка (когда захочется в App Store / Google Play).**
   Тот же React-код упаковывается в нативную оболочку (Capacitor) —
   получаем «настоящие» iOS/Android приложения, пуш-уведомления вместо
   телеграм-напоминаний, иконку в сторе. Кода почти не добавляется.
3. **Offline-first (последний этап).** Локальная БД на устройстве
   (IndexedDB/SQLite) + синхронизация с сервером при появлении сети.
   Это самый дорогой шаг — отдельная фаза, проектировать после PWA.

Бэкенд уже готов к этому: REST API отделён от бота, авторизация —
единственное место, которое надо расширить. Ничего «импортировать» не
нужно — то же приложение, те же данные, тот же сервер.

## Не делаем в этом круге

- Per-unit конвейеризация пайплайна (стадии-барьеры ок для ≤3 пунктов).
- Offline/PWA — отдельная фаза (см. выше), не смешиваем с баг-фиксами.
- Восстановление досок из корзины — фича-кандидат в бэклог.
